# UCL Design System — Reference for Architecture Assistant

This file is the **authoritative design specification** for all UI surfaces in this
project. It follows the UCL Design System published at
https://www.ucl.ac.uk/brand-and-experience/experience/ucl-design-system.

When building or changing any UI component — web or future mobile — use the tokens,
patterns, and rules defined here. Do not use arbitrary values not mapped to a token.

---

| Token | CSS variable | Hex | Usage |
|---|---|---|---|
| Vibrant Purple | `--color-vibrant-purple` | `#500778` | Strong accent, data visualisation |
| Success | `--color-success` | `#52C152` | Positive feedback, success alerts |
| Error | `--color-error` | `#D50032` | Destructive actions, error alerts |
| Warning | `--color-warning` | `#FFCA36` | Caution states, warning alerts |
| Info / Focus | `--color-info` / `--color-focus` | alias of `--color-accent-blue` | Informational alerts, focus rings |

### Colour rules
- Lead with dark purple, off-white, and purple accents.
- Use bright purple only on white or off-white backgrounds.
- Use mid purple on dark purple backgrounds where contrast is needed.
- Use light/pale purple for panels, callouts, and background sections.
- Use heritage blue sparingly: CTAs, focus rings, and active state borders only.
- All colour pairs must meet WCAG 2.1 AA: ≥ 4.5:1 for body text, ≥ 3:1 for large text.

## Typography

### Typeface
- **Primary:** UCL Sans (custom, based on Google's DM Sans)
- **CDN fallback:** `"DM Sans"` — loaded from Google Fonts (`fonts.googleapis.com`)
- **System fallbacks:** `"Aptos"`, `"Segoe UI"`, `"Helvetica Neue"`, `Arial`, `sans-serif`

CSS variable: `--font-family-base`

### Font weights
| Weight | Value | Usage |
|---|---|---|
| Bold | 700 | Buttons, strong emphasis |
| Semi-bold | 600 | Headings, labels |
| Regular | 400 | Body copy |
| Light | 300 | Designed layouts only |

## Components

The UCL Design System defines these components. Match the CSS class names and HTML
patterns below in all implementations. All component styles live in `styles.css`.

| UCL component | CSS class(es) | HTML element |
|---|---|---|
| Alert | `.alert` + `.alert-info / .alert-warning / .alert-error / .alert-success` | `<div role="alert">` |
| Breadcrumbs | `.breadcrumb` | `<nav><ol class="breadcrumb">` |
| Button (primary) | `button` | `<button type="button">` |
| Button (secondary) | `.btn-secondary` | `<button type="button" class="btn-secondary">` |
| Card | `.section-card` | `<section class="section-card">` |
| Checkbox | native `<input type="checkbox">` | standard label association |
| Footer | `.site-footer` + `.footer-inner` | `<footer class="site-footer" role="contentinfo">` |
| Radio buttons | native `<input type="radio">` | `<fieldset>` + `<legend>` |
| Text area | native `<textarea>` | standard CSS applies |
| Text input | native `<input>` | standard CSS applies |
| Toggle | `.toggle-switch` + `.toggle-input` + `.toggle-label` | see Toggle pattern below |

### Toggle pattern

```html
<div class="toggle-switch">
  <input type="checkbox" id="my-toggle" class="toggle-input" role="switch" />
  <label for="my-toggle" class="toggle-label">Label text</label>
</div>
```

The input is visually hidden with the `.toggle-input` class (accessible, focusable).
The `.toggle-label::before` renders the track; `::after` renders the thumb.
Always supply matching `id`/`for` attributes.

## Layout

- Container max-width: `1120px`, centred, padded with `--space-4`.
- Grid: 8-point soft grid for blocks; 4-point for icon and type alignment.
- Use `display: flex` or `display: grid`. Avoid fixed pixel widths on content areas.
- Mobile breakpoint: `760px` — stack grids to single column.

---

## Overall feel

- Clean, institutional, confident, modern.
- Prioritise accessibility, clarity, and strong hierarchy.
- Use generous spacing, simple layouts, and strong typographic contrast.
- Avoid overly rounded, playful, glassmorphism, gradient-heavy, or SaaS-dashboard styling.

---

## Brand motif

The "graphic pillars" motif (`.pillar-motif`) — three vertical bars of increasing
height — is a decorative reference to UCL's brand language. Keep it `aria-hidden`.
Do not reproduce the UCL logo unless official assets are provided.

---

## Interface copy

- Clear, direct, and purposeful.
- Prefer: "Get started", "Run", "Save", "Continue", "Explore", "View details".
- Keep labels short and action-oriented.

---

## Accessibility checklist

- [ ] Skip-to-content link present and keyboard-reachable
- [ ] All `<img>` have meaningful `alt` text, or `alt=""` for decorative images
- [ ] All interactive elements reachable by Tab / Shift-Tab
- [ ] Focus ring visible using `--color-focus` with `outline-offset: 2px`
- [ ] Colour contrast ≥ 4.5:1 for body text; ≥ 3:1 for large text
- [ ] Colour is not the sole means of conveying information
- [ ] `prefers-reduced-motion` disables animations and transitions
- [ ] ARIA roles, labels, and `aria-live` regions used where native semantics are insufficient
- [ ] Form inputs have associated `<label>` elements via matching `for`/`id`

## Separation of concerns

| File | Contains |
|---|---|
| `index.html` | Structure and semantics only. No `style="..."` attributes. No inline `<script>` logic. |
| `styles.css` | All visual presentation. All values via CSS custom properties. No arbitrary hex, px, or em. |
| `app.js` | All behaviour. Use class toggles, not `element.style.*`, for persistent appearance changes. |

---

## Web and mobile surfaces

The current web front end (`src/crisai/apps/ui/`) is the primary interactive
surface. A **mobile app** is a planned future surface.

All layout and component work must be:
- **Responsive-first:** designed for 360 px upward before wider viewports.
- **Touch-friendly:** minimum 44 × 44 px hit targets for interactive elements.
- **Token-based:** the same CSS custom properties serve both web and, eventually,
  a mobile web shell without per-platform style overrides.
